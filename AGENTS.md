# AI instructions

## Project overview

- This application is a self-hosted, offline-capable tarot table built with React, TypeScript, and Vite.
- The production app runs inside Docker. The `Dockerfile` builds the app with Node.js 22, then copies the static build into an nginx container. `docker-compose.yml` publishes container port 80 at host port 8080 (`http://localhost:8080`).
- The container serves the frontend only. There is no application server, account system, or server-side reading storage.
- The current deck, spread, and reading state are stored in the user's browser with IndexedDB. Do not move private reading data to a server or add analytics, accounts, or network dependencies without an explicit product request.
- The PWA service worker provides offline use after the app has been loaded and installed/cached by the browser.

## Project structure

- `src/App.tsx`: application flow and screen composition.
- `src/tarot/`: spread parsing/mapping, secure shuffling and drawing, reading formatting, card UI, and deck gallery.
- `src/persistence/db.ts`: IndexedDB persistence for the current browser state.
- `src/types/tarot.ts`: shared application and deck types.
- `public/decks/cathedral/deck.json`: canonical 78-card deck manifest; artwork is referenced separately.
- `src/styles.css` and `src/theme.css`: application layout and visual theme.
- `vite.config.ts`: PWA and test configuration.
- `Dockerfile`, `docker-compose.yml`, and `nginx.conf`: production container build and static serving.

## Working guidelines

- Keep the app client-side and private by default. Treat the browser's IndexedDB as the source of persistence; restarting the Docker container should not reset a user's deck.
- Keep the deck manifest as card identity and visual metadata. Do not put card meanings or generated interpretations in it.
- Preserve the 78-card deck invariant, unique card IDs, secure random shuffling, and the rule that drawn cards stay out of the deck until the user resets it.
- Preserve the app's existing reading stages: setup, shuffling, and reading. Keep changes focused and maintain accessible labels, status messages, keyboard operation, and reduced-motion support.
- Use the existing TypeScript and React patterns. Avoid adding dependencies when the platform or current packages already provide the needed capability.
- Keep Docker as the production runtime. Changes to build output, routes, service-worker assets, or static asset paths must continue to work through nginx and the Compose port mapping.

## Common commands

- Install dependencies: `npm ci`
- Run the Vite development server: `npm run dev` (inside the development environment; this is not the production container)
- Run tests: `npm test`
- Build and type-check: `npm run build`
- Build and run the production container: `docker compose up -d --build`
- Stop the production container: `docker compose down`

The Docker image has a health check against nginx on container port 80. The `dist/` directory is generated by the build; edit source files rather than generated output.
